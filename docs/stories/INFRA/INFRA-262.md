## Context

Every story `story_new.py` generates is currently born broken. `_story_frontmatter()`
(`skills/pairmode/scripts/story_new.py`, the final `lines +=` block, ~line 67) emits

```
touches:  # If this story changes any documented architecture, add docs/architecture.md to this list.
```

The canonical frontmatter parser (`schema_validator._parse_frontmatter`) treats a key as a
block-sequence start only when its value is exactly `""` or `"[]"` (lines 109-113). The
trailing comment makes the value a non-empty **string**, so `touches` parses as
`"# If this story changes any documented architecture, ..."`. `flex_build.generate_permissions_artifact`
then does `for p in primary_files + touches` (line ~371) and raises
`TypeError: can only concatenate list (not "str") to list`, which surfaces inside
`create-story-worktree` — the very first step of the build loop. Phase 102 hit this live on
INFRA-259; it was cleared only by hand-editing the frontmatter, and the orchestrator
pre-fixed INFRA-261/262's stubs by hand before this phase could start. `tests/pairmode/test_story_new.py::TestTouchesArchitectureComment::test_story_frontmatter_touches_has_architecture_comment`
(line 661) asserts the comment is on the `touches:` line, so the test suite actively pins the
defect.

This story fixes **both** halves, and the two halves do different jobs:

- Fixing the generator stops *new* stubs from being born broken.
- Hardening the parser unblocks the **20 story files already on disk** that carry the
  `touches:  # …` line (`grep -rln "^touches:  #" docs/stories/` → 20 files, mostly the
  RELEASE-044…061 backlog block) without a mass rewrite of story specs, and protects fleet
  consumers whose stubs were generated by older plugin versions.

There is direct precedent for the parser half: INFRA-211 (CHANGELOG `HARNESS015-main`) already
taught `_parse_frontmatter` to strip inline `#` comments from block-sequence *list items*, with
quote-exemption, via `_strip_list_item_comment()` / `_INLINE_COMMENT_RE`. This story extends the
same, already-agreed semantics one line up to scalar values. That is a deliberate choice over
inventing a second comment rule: one comment rule for the whole minimal-YAML subset is what
`docs/architecture.md`'s "canonical frontmatter parser" claim is worth.

The quote-exemption is load-bearing, not decorative: `docs/stories/INFRA/INFRA-074.md` line 4
is `title: "Story contract sections — ## Requires / ## Ensures"` — a quoted scalar containing a
whitespace-preceded `#`. Naive scalar comment-stripping truncates it to `Story contract sections
—`. The quote check must run before the comment strip, exactly as `_strip_list_item_comment`
already does.

## Ensures

1. `story_new._story_frontmatter()` emits the `touches` key as `touches: []` — a line that is
   exactly `touches: []` with no trailing `#` comment and no trailing whitespace-plus-text.
   Assertable as: `"touches: []" in output` and no line of the output both starts with
   `touches:` and contains `#`.

2. The INFRA-186 architecture prompt survives, relocated outside the frontmatter block:
   `story_new._story_body()` begins with an HTML comment naming `docs/architecture.md` and
   instructing the author to add it to `touches:` when the story changes documented
   architecture. A generated story file therefore still contains the string
   `docs/architecture.md`, but it appears strictly **after** the closing `---` of the
   frontmatter block (verifiable: the index of `docs/architecture.md` in the file text is
   greater than the index of the frontmatter's closing `---`).

3. `story_new._story_frontmatter()` quotes the `title` value when the title contains a
   whitespace-preceded `#` (i.e. emits `title: "…"`), so that operator-supplied titles are not
   truncated by the scalar comment-stripping added in Ensures 4. Titles without such a `#` are
   emitted unquoted exactly as today.

4. `schema_validator._parse_frontmatter()` strips trailing inline comments from **scalar**
   values using the same rule already applied to block-sequence list items (INFRA-211): a `#`
   preceded by whitespace or at the start of the value begins a comment; a `#` glued to
   non-whitespace content does not; a value that is wholly quoted (matching leading/trailing
   `"` or `'`) is returned verbatim with quotes removed and **no** comment stripping applied.
   The list-item path's behaviour is unchanged.

5. Comment stripping happens **before** the block-sequence-start test, so a scalar line whose
   value is only a comment (`touches:  # …`) reduces to `""` and is parsed as a list start:
   `_parse_frontmatter("---\ntouches:  # note\n---\n")["touches"] == []`.

6. `_parse_frontmatter` returns `title` unchanged for the real-world quoted case:
   parsing `docs/stories/INFRA/INFRA-074.md` yields
   `fm["title"] == "Story contract sections — ## Requires / ## Ensures"` (not truncated).

7. A freshly-generated stub round-trips: writing a story via the `story_new` CLI into a
   `tmp_path` project and reading it back with `flex_build._read_story_frontmatter` yields
   `isinstance(fm["touches"], list)` and `fm["touches"] == []`.

8. End-to-end guard: `flex_build.generate_permissions_artifact(story_id, project_path)` called
   against an **unedited** freshly-generated stub completes without raising, and the resulting
   `docs/phases/permissions/<story_id>.json` has `allowed_paths` containing exactly the story
   spec's own relative path (`docs/stories/<RAIL>/<ID>.md`) — no `TypeError`.

9. Legacy guard: a story file written with the **old** buggy line
   (`touches:  # If this story changes any documented architecture, add docs/architecture.md to this list.`)
   also parses with `touches == []` and also passes the `generate_permissions_artifact` call in
   Ensures 8 — so the 20 already-on-disk stubs are unblocked without editing them.

10. `tests/pairmode/test_story_new.py::TestTouchesArchitectureComment::test_story_frontmatter_touches_has_architecture_comment`
    no longer asserts the comment is on the `touches:` line. It is replaced (same class, renamed
    test) by an assertion that the `touches:` line is bare (`touches: []`, no `#`) **and** that
    the `docs/architecture.md` prompt is present in the generated file body. No test in
    `tests/pairmode/` asserts a `#` appears on a `touches:` line.

11. `tests/pairmode/test_schema_validator.py` contains named tests for: scalar comment stripping;
    scalar comment-only value → list start (Ensures 5); quoted-scalar exemption including the
    `## Requires / ## Ensures` title case (Ensures 6); glued-`#` non-comment (e.g.
    `id: ABC#1` keeps `ABC#1`); and unchanged list-item behaviour.

12. `docs/architecture.md`'s canonical-frontmatter-parser paragraph (the
    `**schema_validator.py is the canonical frontmatter parser.**` block, ~line 770) states the
    inline-comment rule for the minimal YAML subset: whitespace-preceded `#` begins a comment on
    both scalar values and block-sequence items; quoted values are exempt; a scalar whose value
    is entirely a comment is a block-sequence start.

13. `CHANGELOG.md` has an entry under the current unreleased/pairmode section recording the
    generator fix and the parser extension, naming INFRA-262 and CER-092, and flagging the
    parser change as behaviour-affecting for downstream consumers.

14. `tests/pairmode/` passes (no `-x`; the known pre-existing
    `test_observability_ui.py::test_ui_build_emits_dist_index_html` failure is acceptable only
    if it reproduces on clean HEAD).

## Instructions

1. **`schema_validator.py` — generalise the comment stripper.**
   Rename/extract `_strip_list_item_comment()` into a shared helper (e.g.
   `_strip_inline_comment(value: str) -> str`) with the identical body it has today: strip, then
   return `trimmed[1:-1]` verbatim if wholly quoted, else remove the `_INLINE_COMMENT_RE` match
   and re-strip. Keep `_strip_list_item_comment` as a thin alias **or** update the list-item call
   site (line 96) — either is fine, but the list-item path's observable behaviour must not
   change. Update the docstring to say it serves both scalars and list items.

2. **`schema_validator._parse_frontmatter` — apply it to scalars.**
   In the `scalar_m` branch (lines 106-122), replace
   `value_raw = scalar_m.group(2).strip()` +
   the later quote-stripping block with a single call to the shared helper, ordered as:

   - `value_raw = _strip_inline_comment(scalar_m.group(2))`
   - then test `if value_raw in ("", "[]")` → block-sequence start (unchanged logic).
   - then `result[key] = value_raw` — the helper has already removed quotes, so **delete** the
     now-redundant quote-stripping `if` block rather than running it twice (double-stripping
     `"'x'"` would be a new bug).

   Order matters and is the whole fix: comment strip → empty test → assign. Add a one-line
   comment at the branch naming CER-092 so the ordering is not "tidied" back.

3. **`story_new.py` — emit a parseable `touches` line.**
   In `_story_frontmatter()`, change the final block to append `"touches: []"` and keep the
   existing CER-006 comment about `primary_files`, updating the second half of that comment
   (which currently says "the touches: line carries the INFRA-186 architecture prompt") to point
   at `_story_body()` instead.

4. **`story_new.py` — relocate the INFRA-186 prompt.**
   Prepend to `_story_body()`'s returned string an HTML comment, before `## Requires`, e.g.:
   `<!-- If this story changes any documented architecture, add docs/architecture.md to the touches: list above. -->`
   It must be inside the Markdown body (after the frontmatter's closing `---`), so no frontmatter
   parser ever sees it. Do not put it on the line immediately preceding `---`.

5. **`story_new.py` — quote hash-bearing titles.**
   In `_story_frontmatter()`, when the supplied `title` contains a whitespace-preceded `#`, emit
   `title: "<title>"`; otherwise emit it unquoted as today. This is a small guard that keeps the
   parser hardening in step 2 from truncating an operator-supplied title. Do not attempt to quote
   titles containing a `"` character — that is out of scope; the existing corpus has none.

6. **Invert the pinning test.**
   In `tests/pairmode/test_story_new.py`, class `TestTouchesArchitectureComment` (line 658),
   replace `test_story_frontmatter_touches_has_architecture_comment` with a test asserting the
   inverse: the `touches:` line is exactly `touches: []` and contains no `#`; and a generated
   file still contains the `docs/architecture.md` prompt in the body. Rename the class if its
   docstring no longer describes it (e.g. `TestTouchesArchitecturePrompt`). Do not simply delete
   the old test — the prompt's survival is the thing INFRA-186 bought and it must stay covered.

7. **Round-trip and end-to-end tests.**
   - In `tests/pairmode/test_story_new.py`, add the round-trip test of Ensures 7: invoke the CLI
     into `tmp_path` (the existing `invoke(...)` helper and `tmp_path` project layout are already
     used in that file), then import `_read_story_frontmatter` from `flex_build` and assert
     `fm["touches"] == []` and it is a `list`.
   - In `tests/pairmode/test_flex_build_permissions_create.py`, add the Ensures 8 guard: generate
     a stub via `story_new`'s `_story_frontmatter` + `_story_body` (or the CLI) into a `tmp_path`
     project at `docs/stories/<RAIL>/<ID>.md`, call `generate_permissions_artifact`, and assert
     it does not raise and that the written JSON's `allowed_paths` equals `[story_spec_rel]`.
   - Add the Ensures 9 legacy case alongside it, writing the old buggy `touches:  # …` line
     literally into the fixture file so the regression stays pinned even after generators change.

8. **Docs and changelog.** Amend the `docs/architecture.md` paragraph named in Ensures 12 in
   place — add two or three sentences to the existing canonical-parser block; do not restructure
   the surrounding section. Add the `CHANGELOG.md` entry of Ensures 13 to the top-most pairmode
   section, following the style of the INFRA-211 line (`schema_validator._parse_frontmatter()
   now strips inline YAML comments from block-sequence list items …`).

9. **Do not mass-edit the 20 existing story files** carrying the old line. The parser fix is what
   makes them work; rewriting them is a separate, purely cosmetic change and would balloon the
   diff for this story.

10. **Ideology alignment (Step 4a, checked):** no conflict found. No hook is touched (hooks stay
    thin relays), no state writer is added or moved (the sidebar/CLI single-writer rule is
    untouched), and the change strengthens `Never silently pass contradictions` — today the
    malformed `touches` value passes the parser silently and only detonates two call frames later
    inside worktree creation. The one adjacent constraint worth naming is the *canonical parser*
    convention in `docs/architecture.md`: rather than routing around it (e.g. teaching
    `flex_build` to coerce a str `touches` into a list at the call site, which would re-implement
    parsing at a consumer), the fix lands in `schema_validator` itself, preserving the
    "one parser, imported everywhere" rationale rather than just its letter.

## Out of scope

- **Rewriting the 20 existing story files** that carry the old `touches:  # …` line. The parser
  fix makes them parse; a cosmetic sweep is a separate story if ever wanted.
- **Replacing the minimal YAML subset with a real YAML library** (PyYAML/ruamel). The
  stdlib-only, shallow-schema parser is a deliberate standing choice; this story extends it, it
  does not relitigate it.
- **Anchors, multi-line scalars, flow sequences (`touches: [a, b]` with contents), or any other
  YAML feature** beyond scalar/block-sequence + inline comments. `[]` remains the only flow form
  recognised, exactly as today.
- **Quoting titles containing `"`**, or any broader escaping/serialisation layer in
  `story_new.py`.
- **`create-story-worktree`'s own error handling.** Making it degrade gracefully on a malformed
  frontmatter (rather than propagating `PermissionsCreateError`) is a separate hardening story;
  this one removes the cause, not the blast radius.
- **`phase_new.py` / era templates.** A repo-wide grep shows `story_new.py` is the only generator
  emitting a trailing-comment frontmatter line; no other template is changed here.
- **INFRA-261's vendored-`node_modules` work (CER-090).** Separate story, disjoint files.
