# Changelog

All notable changes to flex are documented here. This project loosely follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Pairmode-specific
changes are marked `[pairmode]`; modifications to flex core are marked `[core]`.

## [Unreleased]

### Fixed [pairmode] — Phase 138 (Close shadow-reviewer scope_guard cwd-resolution gap, CER-176/177/201)
- INFRA-408 replaced `scope_guard.check_path`'s shadow-reviewer resolution with a strict cwd-only derivation: the permitted worktree root is derived by walking the tool call's own real cwd against `<main>/.pairmode-worktrees/<ID>/`, never from `file_path`'s own spelling and never from a `state.json` fallback, so a shadow-reviewer write is confined to exactly `<that-worktree>/.pairmode-suggestions.md` with no path letting it land in a different story's worktree or a harness-owned path (CER-177, duplicated as CER-201). Also closed `git diff --no-index <path> <path>` as an unscoped read/write escape in `reviewer_bash_guard.py`'s shadow-reviewer denylist — `--no-index` takes two filesystem paths outside any repository entirely, slipping past every repo-scoped path check, so it's now denied on its own terms via `_SHADOW_REVIEWER_DENIED_GIT_FLAGS` (CER-176).

### Fixed [pairmode] — Phase 137 (Overrides/audit key-shape quality fixes, CER-182/184/185/202)
- INFRA-407 closed four residual gaps left behind by the Phases 123/128/129 `.pairmode-overrides` key-shape change: `audit.py`'s stale-shape diagnostic now suggests a corrected key that the shared `_normalise_override_key` helper itself accepts (CER-182); that same helper is now the single case/whitespace rule shared by `audit.py` and `pairmode_drift_report.py`, so a mixed-case override key can no longer be clean in one tool and a finding in the other (CER-185); `lesson_review.py`'s `.pairmode-drift-rejected` persistence now falls back to a read-only lookup under the pre-CER-181 key shape on a current-shape miss and rewrites the record under the current shape, making stranded pre-change records reachable again (CER-184); and `audit.py`'s remediation text for an overrides-shape finding is now specific to that finding instead of the generic remediation string (CER-202).

### Fixed [pairmode] — Phase 136 (Fleet-gate coverage and leak-closure fixes, CER-190/191/197/206)
- INFRA-406 closed four coverage/leak gaps in the fleet-name reconciliation gate: `scrub_fleet_names.py` now matches fleet names case-insensitively and narrows the domain-suffix leak exclusion to genuine embedded email/subdomain contexts, closing a bare-domain-suffix leak (CER-190); `fleet_discovery.py`'s candidate derivation now accounts for and surfaces every reserved-key drop instead of silently shrinking the candidate count (CER-191); its `--json` output anonymization now recurses over the full result structure so nested `duplicate_hooks`/`machine_absolute_hooks` strings are scrubbed too (CER-197); and its CLI now fails loudly with a non-zero exit on a malformed local fleet config instead of silently degrading to the default fleet root, while the underlying library functions keep their existing never-raises contract (CER-206).

### Fixed [pairmode] — Phase 135 (Fleet-gate trivial quality fixes, CER-189/198/199/203/204/205)
- INFRA-405 closed six small, independently-scoped quality gaps in the fleet-name reconciliation gate: `.pairmode-fleet.local.json.example` now uses self-evidently-fake placeholder labels instead of realistic-looking names (CER-189); `fleet_map.load_local_fleet_map` raises `FleetMapConfigError` on a present-but-non-dict top-level JSON value instead of falling through to a false clean pass (CER-198); `scrub_fleet_names.py`'s generated pre-commit hook shell-quotes its interpolated values via `shlex.quote` (CER-199); `--root` with no following value now raises instead of silently falling back to `_FLEX_ROOT` (CER-203); `verify()`'s `mapped=`/`excluded=`/`unmapped=` reconciliation summary now prints unconditionally instead of only on the success path, where the `unmapped=` count was structurally always zero (CER-204); and the mapped/excluded conflict check now goes through the shared `fleet_map.normalize_name` case-fold instead of a case-exact comparison (CER-205).
